# 多平台执行约定

这是Codex执行的浏览器业务流程，主数据为JSON/CSV。探索任务先用 `python demo.py task TASK_ID --begin` 打开，再读取返回的项目上下文。平台选择、观察及实测状态以该项目当前记录为准。

浏览器统一为 [Playwright MCP](browser.md)，使用项目browser.mjs或同一个已连接MCP。实时验收状态以platform_checks为准；依赖安装及登录方式见 [部署与安装](../部署与安装.md)。

## 平台契约

| 项目 | 小红书 | 抖音 |
|---|---|---|
| platform | xiaohongshu（兼容 xhs/小红书） | douyin（兼容 dy/抖音） |
| 搜索 channel | xhs | douyin |
| 公开入口 | https://www.xiaohongshu.com/ | https://www.douyin.com/jingxuan |
| 作品身份 | /explore/笔记ID | /video/数字ID 或 /note/数字ID |
| 账号身份 | /user/profile/账号ID | /user/公开账号ID |
| 创作中心 | https://creator.xiaohongshu.com/ | https://creator.douyin.com/ |
| 本地封面模板 | 1080×1440 | 1080×1920 |
| 自定写作阈值 | 标题20 / 含标签正文1000字符 | 标题30 / 含标签描述500字符 |

模板尺寸和写作阈值是本项目的设计选择，未宣称平台官方限制。上传要求、标题/描述计数、AI标识、话题挂载、实际裁切必须到对应平台实际核验。抖音创作中心不能沿用小红书的规则证据或账号。

## 场景B：每轮多平台探索

1. 请求platforms可选小红书、抖音、web（网页搜索），允许单独选web。主动发现按勾选渠道执行，未选web仍可访问官网核验候选。用户填写探索要求、可配初始词；继续项目继承历史，素材不绑定探索。web不是发布平台。
2. 先复查高价值来源，再结合要求和种子选择入口。只限制本轮最大搜索次数，默认50次，可在创建任务时修改。正文、同行／来源、官方公告阅读和整轮时间均不限，不设最低搜索或渠道覆盖次数；按所选渠道和线索价值开展搜索，受阻记录实际缺口。搜索摘要不算正文，计数只用于追踪真实进度。
3. 在统一Playwright MCP会话中列标签、选择对应平台页（无则新建），先读快照再使用实际可见的搜索框。按结果质量选择综合或最新（若当前界面支持），记录实际排序与时间筛选；未看到筛选不能写“最近7天”。不要使用凭空猜测的定位器、私有接口、签名/反爬绕过或后台抓取。
4. 从结果进入实际视频/图文详情，读取可见描述、作者、发布时间、话题和互动量。仅看描述不能说看完视频、听过音轨。正文不可读时只保存摘要线索；不得填 read_at 或 post_reads。
5. 每条提取新作品、主题、创作者、机构或活动，写 followups（含 platform、parent_url、reason），结合相关性、新信息、可信度和时间选下一分支。相同关键词在两个平台保留独立分支；不把第二个平台当作重复关键词列表机械跑完。
6. 同行主页必须实际打开，保存该平台公开账号和 seen_posts；规模/发展阶段未知如实记录。换平台时先验证两账号属于同一创作者，不凭昵称合并。已读作品按平台内容ID去重，续搜不重复计新增。
7. 通过官方公告核验，社交转述只作发现入口。交付候选机会的条件、证据和价值评分，关键未知显式标记；素材仅作排序加分，不成为候选门槛。不虚构跨平台增长、奖金收入或成功概率。

## 互动采样与热点

`python demo.py research snapshot 文件.json` 保存一次真实观察：platform、source_type（platform_browser/web_index/manual）、query、sort、time_window、scope_note、items。每条 item：url、title、published_at（带时区或null）、body_read、metrics（likes/comments/shares/favorites，未知为null）。近似计数请另存 metrics_display、说明近似值，不能装成精确值。

搜索引擎摘要用 web_index，不能登记正文已读或实时互动数，不增加站内覆盖。平台采样用 platform_browser。保存采集时刻、时间筛选、排序和样本偏差。一次采样可以说明“这一批样本的互动表现”，不能推导趋势或平台搜索量；比较需同平台、同方法、相同时间范围的历史快照，说明样本变化与局限。不得把不同平台的绝对点赞量直接排名。没有榜单证据的标签仍标“相关性建议/热度未知”。

`python demo.py research check 文件.json` 保存 platform、capability（search/detail/peer/draft）、status（verified/blocked/untested）、note。实测通过还需实际 url、read_at、excerpt；遇连接/登录问题记录 blocked，写具体发生在哪一步，不把接口已实现当真实页面已跑通。

页面能力以本轮实际访问为准。首页可读、搜索可用、原帖可读和草稿填写分别验收；访问失败写入当前检查记录，不据旧会话结果推断平台永久可用或不可用。

## 场景A：同一素材的独立平台包

create 输入 `platform` 和 `asset_id`（或同项目 plan_id/action_id）。同平台、同来源、同素材版本才复用未结束包。跨平台可沿用项目事实、内容简报和真实审片范围，文案另写；不能自动复制小红书长文、封面、账号、平台规则、确认和回执。

抖音版先明确视频是什么、有什么观看问题，用较短描述和相关标签。是否重剪取决于素材表现与工时，不因为平台不同就承诺竖屏重剪。生成对应模板 PNG，实际打开检查，并保存素材版本。所有标签先作为文本建议，未宣称已关联平台话题或掌握热度。

准备包、平台草稿和发布分开验收。账号与规则证据必须匹配平台；作品回执必须为该平台实际作品详情，首页/搜索页/未展开短链均拒绝。开发适配不构成上传授权；继续遵守发布 Skill 的具体账号/版本确认流程。

## 后续增加平台

修改 `platforms.py` 的配置与 URL/账号规范，补入此文件的浏览器执行约定和平台事实来源，再加身份归一、隔离、回执、覆盖、封面测试。共用项目/素材/Frontier/周计划/发布版本的数据层。新增配置只代表本地接入；浏览器搜索、正文、同行和草稿必须分别实际验收后才能标 verified。无需引入数据库、多 Agent 或复杂调度器。

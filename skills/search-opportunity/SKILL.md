# 从小红书首页发现好机会

在 `operating_agent` 目录工作。输出按价值排序的候选机会，原文、判断、互动状态和发现记录跨轮次保存在文件中。

## 打开任务

收到任务 ID，直接运行；任务已绑定项目，不要重新创建项目：

```text
python homefeed.py task TASK_ID --begin
```

`next_action` 为 `browse` 才开始；`stop` 则保存已完成操作并结束；`report` 只汇报，不重新浏览。重复打开复用同一任务。不要用旧的 `demo.py task/start/record`、线索库或种子词。

任务上下文含 `project`（名称、偏好方向、五项权重）及该项目的历史笔记。偏好可为空；不套用其他项目的偏好。开始前实际确认小红书已登录；页面勾选本身不证明登录有效。

没有任务时优先让用户在网页新建/继续项目，避免猜项目设置。用户已明确要求直接开始且没有其他要求时，可创建不填偏好的项目：

```text
python homefeed.py start --logged-in --new --name "新探索"
python homefeed.py task TASK_ID --begin
```

继续已有项目可用 `python homefeed.py start --logged-in --project-id PROJECT_ID`，它复用项目偏好、权重和历史。每个项目独立积累；同一浏览器同时只执行一个任务。网页保存后给出可复制提示词，本身不自动驱动浏览器。

## 浏览首页

用项目 Playwright MCP：先 `node browser.mjs tools`、`node browser.mjs snapshot`。连接方式及带签名链接处理见 [浏览器说明](../../references/browser.md)。只复用当前登录，不复制 Cookie，不另外安装抓取器。

打开 `https://www.xiaohongshu.com/explore`，先确认“我”等登录状态和实际账号。账号不符、登录失效或验证码时由用户处理；不要切换账号或关注作者。

反复执行：

1. 读取当前任务状态和历史 `seen_notes`，检查是否已请求停止。
2. 刷新首页（首次打开也计一次），等推荐卡片实际加载，阅读卡片并适当下滚。记录实际浏览的卡片数量。不要快速高频刷新。
3. 点击有共创、合作、比赛、征集、孵化等可能的原帖。理解正文，必要时看活动海报；不能把标题或搜索摘要当成核验。
4. 判断价值、开放时间、参与门槛和授权。跟进原帖直接给出的官方正文可以用于核验；不通过站内搜索或网页搜索扩展另一套发现流程。明确过期或不相关的记录跳过原因。
5. 保存有实际依据的候选并评分。未知条件写明，转述不能冒充官方。不建立作者档案或官方账号清单；核验公告身份的依据只保存到机会证据中。
6. 对确实值得参与、当前开放且有明确价值依据的原帖点赞、收藏，按下节处理。返回首页继续；新任务复用历史去重。

每读一小批就保存，网页显示真实进度，不等整轮结束。用 [记录格式](record-format.md) 的 `python homefeed.py record 观察包.json`。同一观察包重传不重复计数。`homepage.json` 是主记录；JSON/CSV/Markdown 都方便人工查看。

## 点赞收藏

任务的 `allow_interactions` 必须为 true。只操作当前正在阅读、笔记 ID 已核对的原帖。

- 先通过可见图标、DOM 可访问状态或页面截图确认是否已经点赞、收藏。已完成的记录 `already_done`，不要点击。
- 未完成才通过实际按钮点击一次，重新读取状态，确认后记 `performed`，附前后状态和短证据。
- 状态无法区分、点击报错或网络断开：记录 `unknown/failed`，不盲目重试，不把计数变化当作本人操作成功。
- 绝不点任何“关注/回关/互关”；不私信、不评论、不报名、不支付。

## 评分与停止

评分项为流量扶持、现金激励、商业合作、曝光增长、用户偏好。默认权重依次为30、25、20、15、10；用户可在新建/继续项目时修改，总和100。实际必须使用任务返回的 `project.weights`，不能每轮恢复默认值。每项0至5分按保存的权重换算。前四项权益未知填 null，不加分；它们的非空分数引用7天内实际读过的官方原文。用户偏好分依据已填写的偏好与机会信息给出理由。奖金池不是预计收入，不编造获奖或合作成功概率。

只依据用户填写的项目偏好判断匹配，填 `preference_match: {"score":0至5或null,"reason":"具体依据"}`。未填写偏好时填 null，不猜偏好、不默认加满分。偏好更新后，历史匹配会失效，重新评估才能加分；只改权重则由程序直接重算。

**不读取、不理解、不使用项目素材，也不评估素材匹配。** 项目可单独管理素材，但与本 Skill 的发现和评分无关。不查素材库、不读素材文件，不调用 Gemini。

不设固定刷新、用时或阅读数量，不因看完一屏就结束。根据推荐是否仍出现新内容继续。用户停止、平台阻塞、连续推荐重复且无新价值，或需要结束本轮时，记录真实原因和未确认事项，不宣称穷尽平台。每次刷新和互动前检查任务的停止状态。

```text
python homefeed.py finish TASK_ID --status completed --summary "实际发现、互动结果与停止原因"
python homefeed.py export
```

受阻用 `--status blocked`，仍有待办用 `partial`，用户停止用 `interrupted`。向用户交付网页候选及 `data/首页探索记录.md`，明确实际刷新、阅读、保留和互动数量。
